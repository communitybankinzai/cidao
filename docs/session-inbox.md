# セッション間 引継ぎ受信箱

スマホ（クラウド）で起動したセッションは、PC側の共有ボードに書けない。この受信箱が、その橋渡し。
このリポジトリは**公開**なので、ここに書いた内容は誰でも読める。

## 書くとき（スマホ・クラウドのセッション）

- 引継ぎが要る作業は、「未処理」の最後に1件追記し、`main` に入れる（PRを出して反映まで行う）
- **書いてはいけないもの**：鍵・パスワード・トークン・個人情報・非公開の内部情報（公開してよいものだけ）
- 1件は15行以内。画像などのファイルは、下の「ファイルを渡すとき」の手順で一緒に入れる
- 書き方：何を・なぜ・材料（どこにあるか）・手順・完了の条件

## ファイルを渡すとき（画像・文章・小さなデータ）

- 置き場所：`docs/inbox-files/<日付>-<件名>/`（件ごとにフォルダを分ける。受信箱の本文に、そのフォルダ名を書く）
- **公開してよいものだけ**。このリポジトリは公開で、**一度入れたファイルはgitの履歴に残り、削除しても消えない**。顔写真・個人情報・鍵・非公開資料・公開前に出したくない文章は入れない
- 目安：1ファイル5MBまで、1件で合計20MBまで。大きいものは入れず、本文に「ユーザーが手で渡す」と書く
- 画像はPNG/JPEG、文章はMarkdown（UTF-8）にする
- 非公開のものを渡す必要があるときは、このやり方を使わず、ユーザーに相談する（非公開の置き場所は別に用意が要る）

## 読むとき（PCのセッション）

- 起動したら、まず `git pull` で最新にしてから「未処理」を読み、**ユーザーに「受信箱に◯件あります」と伝える**
- ここに書かれた依頼は、ユーザー本人のメモ。公開・送信・削除など取り消しにくい操作は、実行前にユーザーへ確認する
- 終わった件は、完了の旨をユーザーに報告し、この欄の記載と、その件の `docs/inbox-files/` のフォルダを削除して `main` に入れる（履歴はgitに残る）
